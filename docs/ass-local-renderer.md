# Local ASS/SSA renderer

This document describes the current JavascriptSubtitlesOctopus/libass path used by Ploff for local
ASS/SSA rendering on legacy LG webOS TVs. Historical checkpoint plans and handoff notes live in Git
history; this file is the current architecture and maintenance reference.

## Scope and editor eligibility

Ploff can locally render both external and embedded ASS/SSA when the global ASS rendering setting is
enabled and the playback mode permits it. Renderer enablement is global-only: media/season profiles do
not own `renderAss` or `renderSrt`, and legacy scoped renderer flags are ignored. **Advanced Subtitle
Settings** exposes only controls applicable to the selected track and current renderer owner:

- SRT/SubRip and WebVTT/VTT: editor eligible;
- external ASS/SSA with fetchable original subtitle text: editor eligible;
- embedded ASS/SSA: editor eligible for playback timing and renderer-applicable controls;
- PGS, VobSub, and other image subtitles: Plex playback only.

Plex does not reliably expose the original embedded ASS/SSA payload and may return a lossy conversion.
Embedded ASS/SSA is therefore treated as a playback-settings source, not an editable original subtitle
document. Offset, loop and preview timeline remain available. Size is enabled only while the local ASS
renderer owns the pixels. Background and edge stay disabled because the ASS document/libass owns
appearance. `SubtitleSync.classify()` and `editorCapabilities()` are the codec/source and row-capability
contracts; `SubtitleRuntime` remains the runtime authority for playback-mode and session-failure
eligibility.

### Global renderer controls

Advanced Subtitle Settings keeps the SRT/WebVTT and ASS/SSA renderer rows visible, but both are
proxies for global Settings rather than media/season overrides. Enabling or disabling either row
requires an explicit Yes/No confirmation through the existing choice-dialog navigation. No is the
safe default and Back is equivalent to declining. A confirmed global change is applied to current
playback immediately; later cancelling the editor does not roll that global decision back. Force
Transcode remains server-owned regardless of the global local-renderer switches.

## Legacy Chrome 53 cold start

Legacy LG webOS exposes Chrome 53 without WebAssembly, so Ploff uses the asm.js
`subtitles-octopus-worker-legacy.js` path. Cold-start work is deliberately overlapped with application
startup while keeping exactly one libass worker:

1. `app/startup-metrics.js` runs from the document head and creates the one legacy worker only when
   the persisted global ASS rendering setting is enabled. With ASS rendering OFF, no startup worker is
   created.
2. When enabled, the preloader sends `worker-init` immediately, so static memory, packaged fallback
   font, libass, and a tiny bootstrap `ASS_Track` with one synthetic Dialogue are prepared before
   playback needs them. Initial worker creation does **not** render that Dialogue.
3. After the first Home surface reports ready, `ApplicationController` defers one event-loop turn and
   asks the preloader to perform one glyph-bearing render inside the Dialogue window. That single
   measured step completes warmup; the former empty-state second step was removed because TV data
   showed no reduction in first real-track render cost. The deferred callback rechecks the global ASS
   setting before doing work.
4. `app/libass-subtitle-renderer.js` can claim that same initialized worker at any time; it never
   creates a second libass instance. Claiming it cancels remaining synthetic warm work, so immediate
   playback wins over speculative startup work.
5. Plex Detail metadata is parsed once and its inline media profile is reused to resolve an external
   ASS track without a second metadata request in the normal path.
6. `app/ass-subtitle-prefetch.js` fetches the selected external ASS as soon as it is known;
   `AssSubtitleRendererPool.prepare()` can place the real track on the warm worker before Play.
7. Foreground playback joins in-flight prefetch work and latest-wins ordering prevents stale
   speculative preparation from delaying the requested media.

The remote/non-local Plex subtitle path remains separate and unchanged. Embedded ASS extraction must
not start speculative transcode sessions merely because Detail was opened.

## Worker profile and rendering hot path

The checked-in legacy worker is generated by `scripts/slim-ass-legacy-worker.js` from the archived
upstream source. The native payload stays byte-compatible with upstream, but Ploff initializes its
single packaged fallback font directly with `ASS_FONTPROVIDER_NONE`; linked Fontconfig therefore
stays dormant at runtime. The profile keeps only the JS bindings needed by Ploff. Its Emscripten static memory is stored in
`subtitles-octopus-worker-legacy.mem` so Chrome 53 does not parse thousands of base64 JavaScript
fragments.

Real `setTrack()` replaces only the active `ASS_Track`: the existing `ASS_Library` and `ASS_Renderer`
are preserved so their font/glyph/bitmap caches survive track replacement. The historical
`ploff-warm-cancel` message remains only as an adoption guard so the bootstrap track is not rendered
by the resize that happens while ownership moves to foreground playback.

Static ASS tracks are event-driven rather than polled at a fixed FPS. Ploff classifies karaoke,
`\\t`, `\\move`, `\\fad`/`\\fade`, and non-empty ASS Effects as animated and keeps those tracks at
24 fps. For a static track the worker reads Start and Duration from libass's already parsed
`ASS_Event` objects, builds the ordered Start/End boundary list, and renders only when playback enters
a new boundary state. If classification or boundary extraction is unsafe, the track falls back to
the full animated cadence.

During normal playback the static boundary cursor is monotonic. Small backward corrections from the
media clock cannot revisit an already consumed state and resurrect a subtitle that has just ended.
An explicit `seekAbsolute()` is different: when the seek actually commits, the controller advances a
subtitle `playbackEpoch`, resets the monotonic cursor/presentation barrier, and notifies the worker.
For debounced seeks this reset deliberately waits until commit, so clock samples from the old native
position cannot contaminate the new epoch. The committed target then becomes valid immediately while
queued frames from the previous epoch are dropped.

The bitmap that was already **actually presented** is handled separately from those logical barriers.
For a static ASS state, main retains only its lightweight `[validFrom, validUntil)` metadata. A committed
seek that still lands inside that exact state window leaves the current canvas untouched, avoiding an
unnecessary subtitle blink. A seek before `validFrom` or at/after the exclusive `validUntil` clears the
stale canvas immediately rather than waiting for the first worker frame at the new position. This check
uses presentation metadata, never `renderFramesData`, because that slot may already contain a newer frame
that has been received but has not yet passed browser RAF presentation. Animated/karaoke rendering remains
on its independent continuous path and is not treated as a reusable static bitmap.

The main-thread presentation barrier is the final guard. It remembers the media time and boundary
index of the last frame that was **actually drawn**, and each static worker frame carries
`boundaryIndex`, `validFrom`, and `validUntil`. A frame is rejected if it belongs to an old epoch or
render generation, regresses behind the last presented state, or finishes after its real libass
validity interval has expired. A frame that arrives before `validFrom` is not rejected: its independent
RGBA buffers are retained in the prepared queue and presented only after the media clock enters that
validity window. The check is repeated inside the browser RAF, so a frame that becomes stale while
waiting to paint is still discarded. No arbitrary "old by N ms" threshold is used.

For static tracks the main thread retains at most five **memory-bearing** future boundary states and
at most 16 MiB of prepared RGBA data. The queue contains complete libass boundary states rather than
Dialogue lines. A state whose rendered payload contains no RGBA bytes (for example an empty canvas
gap) is still retained in temporal order but does not consume one of the five costly slots. Such
zero-byte states may therefore extend the queue beyond depth five while `preparedCostlyDepth` remains
`<= 5`; the explicit 16 MiB byte budget remains the absolute RGBA guard. The nearest costly states win
when either quota is reached. A prepared deadline timer is only a wakeup mechanism: pause, resume, rate
changes and timer jitter always re-check the expected media time before a cached frame can be drawn.
The wakeup is re-armed for every strictly-future `validFrom`, even inside the one-millisecond
anti-jitter presentation tolerance, so a near-boundary timer cannot fall through and wait for the next
coarse playback clock sample.

The single worker acts as a bounded-cost lookahead producer. Once the real playback state is committed
it scans future boundary states in order and may continue across any number of already prepared
zero-byte gaps until five memory-bearing states are acknowledged or the track ends. The nearest
unprepared state has priority; deeper states require conservative slack based on recent libass render
cost. Speculative rendering never advances the committed static boundary cursor, and an already
prepared boundary is not rendered a second time when playback reaches it. After a long blocking render
the latest real media clock wins and expired intermediate plans are skipped rather than replayed. Five
acknowledged **costly** entries form the producer occupancy limit; zero-byte entries are reported
separately and do not stop useful deeper lookahead. Superseding a prepared copy with a live frame
updates that occupancy immediately instead of waiting for browser RAF presentation.

Render-time override state is deliberately nullable. `null`/`undefined` means **use the live
extrapolated playback clock**; only a finite numeric value is an explicit lookahead render time. Do
not normalize the nullable state through `Number()` before checking it, because `Number(null) === 0`
would silently force every ordinary render to media time zero. A real legacy-worker regression uses a
replacement ASS whose first event begins at 15:00 while playback is at 15:01 so this contract cannot
again be masked by fixtures that happen to contain a subtitle at 0:00.

Two independent invalidation domains keep speculation safe. `playbackEpoch` changes only for an
explicit committed timeline discontinuity such as a seek. `renderGeneration` changes when cached
pixels become invalid because the track, subtitle style/size or effective render geometry changes.
Every worker result carries both values; old results can therefore finish after an uninterruptible
`ass_render_frame()` without becoming eligible for presentation.

Changing the user-selected ASS synchronization offset is also a deliberate timeline discontinuity.
Before rendering with the new shifted ASS clock, the runtime opens a new playback epoch at that shifted
time. This permits intentional backwards offset corrections while invalidating prepared states from the
previous offset.

Combined playback clock packets are also ordered atomically on resume: `isPaused=false` is applied
before the new media time, preventing `setCurrentTime()` from entering a long synchronous libass
render while the worker still believes playback is paused.

Playback-rate changes re-anchor both the main-thread prepared clock and the worker extrapolated clock at
the exact change timestamp before the new rate is applied. This prevents either side from retroactively
applying the new rate to time that elapsed under the previous rate.

The `js-blend` bitmap conversion uses a byte-equivalent packed `Uint32Array` fast path on supported
little-endian runtimes with a bounded alpha LUT and a byte-wise fallback. The packaged
`default.woff2` is loaded synchronously during `preRun` when valid; the asynchronous fallback owns an
explicit run dependency that is released on success, XHR failure, invalid data, or setup exception,
so font failure cannot deadlock libass startup.

Do not reintroduce `wasm-blend`, another worker, additional cold-start fonts, or broad worker features
without TV measurements and focused compatibility tests.

## Readiness and telemetry

Ploff does not treat the upstream `onReady` callback alone as proof that the renderer is usable. The
wrapper probes `getEvents()` through one bounded readiness state machine. Worker timing uses the
dedicated `ploff-ass-timing` message protocol rather than console serialization.

The privacy-safe collector records bounded startup phases plus a continuous 60-second ASS ring buffer
(also capped at 1024 entries). Changed frames carry a monotonic `frameSeq`, an eight-hex
geometry/pixel `frameFingerprint`, their playback epoch, render generation and libass validity window.
Prepared activity is recorded with bounded `prepared-frame`, `prepared-presented`, `prepared-dropped`
and `prepared-invalidated` stages plus total queue depth, `preparedCostlyDepth`, bytes, worker
`workerPreparedCostlyDepth`, and lookahead counters. Home warmup telemetry exposes
`warmFirstFrame`, `warmStepCount`, `warmTotalMs`, `warmMaxMs`, and `warmComplete`. Rejected frames
record only bounded reasons such as `backward-time`, `backward-boundary`, `expired-window`, `epoch` or
`generation`; `future-window` is a deferred prepared state rather than a rejection. It does not retain
Plex URLs, stream IDs, subtitle text, font names, or arbitrary diagnostic payloads.

Useful browser-console snapshots:

```js

```

## Verification

Changes to this path require the normal repository gates plus the focused worker tests:

```sh
npm run build:ass-legacy-worker
npm run check:ass-legacy-worker
node tests/test-ass-legacy-worker-profile.js
node tests/test-ass-js-blend-optimization.js
npm run verify
npm run test:memory
git diff --check
```

The generated worker, `.mem`, `app/app.js`, and styles must remain synchronized with their source
generators. Physical-TV timing remains the final authority for cold-start performance.
